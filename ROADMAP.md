XmlCraft is a clean-room, open-source XML editor built to match the feature set of the leading commercial XML editors, written in Rust with egui, like its sibling [PdfCraft](https://github.com/storytold/pdfcraft). The first release (0.1.0) is an XML editor with XSD and DTD support, validation, schema generation from XML, and sample XML generation from schemas. JSON and YAML follow.

## Headline numbers

- **Feature breadth: 11.5% shipped** (22 shipped and 128 partial of 191 counted features; 64 P0, 62 P1, 56 P2, 9 P3; 8 out of scope), 45.0% weighted, from `cargo xtask parity`. The editor opens, edits, colours and saves XML files byte-faithfully; validation against a DTD and an XML Schema, Entry Helpers from either, Assign Schema (with the bundled schemas chosen from a list), go to definition and a check of an XML Schema itself, a schema resolution trail, XInclude expansion, completion of the names a document uses and of IDREF values, and the generators (schema inference, sample XML, with their dialogs) work; quick fixes cover the common well-formedness problems and required attributes; JSON, JSONC, JSON5, JSON Lines and YAML can be opened, checked, outlined, folded, coloured and typed in, with JSON Schema validation, completion and hover (all partial); a `.bson` file opens as its Extended JSON text and is saved back as BSON, with completion and hover from the schema its text names (partial); JSON Schema inference and a sample from a JSON Schema are partial; the rest of the bundled schema set is not there yet.
- **W3C xmlconf** (XML 1.0 fifth edition, validating, namespace-aware): not-well-formed **100%** (1017 of 1017), valid **100%** (721 of 721), invalid **100%** (227 of 227; the baseline is empty). W3C **xsdtests** (XML Schema 1.0, 2007 release, accepted tests): **98.23%** (37,754 of 38,436; schemas 96.21%, instances 99.34%; 682 known failures are the baseline).

A document is dirty when its text state differs from the saved one (undoing back to the saved text is clean again) or its encoding does. `Session` holds the documents (opening an open file shows it, also when reached by another path to the same file; closing shows the neighbour). `xmlcraft-platform` (native only) reads only regular files, with a size limit that also holds while reading, and a stamp taken from the open handle that is read again if the file changed meanwhile; it writes atomically through `craft-atomic` (no staging file left; a symbolic link, even a dangling or chained one, keeps its link) and notices a file changed or removed on disk (size, modification time, and on Unix the inode change time and file identity, so a same-size write that restores the time is seen). The shell wiring (tabs, the editor, Open/Save, unsaved-changes prompts, drag and drop) is next.
