# XmlCraft roadmap

**Stage: pre-alpha** · now: M1 (text editor and XML syntax); M0's release dry run builds all six targets, install-and-launch is verified on Windows ARM64 only

> **Last reviewed:** 2026-10-27 · **Last updated:** 2026-10-27 · **Change:** M1.1–M1.7 · **Target:** Altova XMLSpy (feature set described in its public documentation)

XmlCraft is a clean-room, open-source XML editor in the spirit of Altova XMLSpy, built in Rust with egui, like its sibling [PdfCraft](https://github.com/storytold/pdfcraft). The first release (0.1.0) is an XML editor with XSD and DTD support, validation, schema generation from XML, and sample XML generation from schemas. JSON and YAML follow.

## Headline numbers

- **Feature breadth: 3.3% shipped** (5 shipped and 4 partial of 152 counted features; 64 P0, 48 P1, 25 P2, 15 P3; 10 out of scope), from `cargo xtask parity`. Everything shipped so far is the application shell and agent control; nothing edits XML yet.
- **W3C xmlconf** (XML 1.0 fifth edition, non-validating, namespace-aware): not-well-formed **64.7%** (658 of 1017), valid **100%** (721 of 721), invalid **100%** (227 of 227); the 359 known failures all need the DTD (M2). xsdtests start with M3.

## Progress log

- 2026-10-27: M1.7 XML colouring. `xmlcraft-syntax::Highlighter` colours a line at a time from the lexer's mode at the line's start (it remembers the start mode of each line it has seen and lexes forward only as far as the line asked for), with 14 classes (punctuation, element and attribute names and values, references, comments, CDATA, processing instructions, the XML declaration, DOCTYPE and declarations, literals, errors). Property: lexing line by line from the saved modes gives exactly the tokens of lexing the whole text. The editor model reports the first changed line per version, the widget tells a `LineStyler` before drawing, and the shell's `XmlStyler` forgets only what an edit made stale. `SyntaxTokens` (light and dark) are checked for 4.5:1 contrast against the editor background. Looked at in both themes with the `editor_shot` example.
- 2026-10-27: M1.6b `xmlcraft-code-editor` (L7): the egui editor widget over `xmlcraft-editor`. Virtualised (only the lines on screen are laid out; a line over 4096 characters is laid out in a window around what is visible, so a megabyte on one line scrolls like a short one), a fixed gutter with line numbers, current-line wash, selections and several carets, tabs expanded to stops, control characters shown as dots, colouring through a host-supplied highlighter, caret blink, scroll-into-view, mouse (click, shift-click, command-click adds a caret, drag with edge scrolling, double click word, triple click line, gutter click line), keyboard with per-platform bindings (a pure table with tests), clipboard events, and input methods (the composition is drawn at the caret and enters the document, and the undo history, only when committed). The host passes colours; the crate knows no theme. egui kittest tests drive typing, keys, mouse, clipboard, IME, read-only mode and the virtualisation; a `shot` example renders it for a visual check (CJK shows as boxes until gap 11 closes).
- 2026-10-27: M1.6a `xmlcraft-editor` (L5, wasm-clean): the headless editor model. An `Editor` owns the buffer, undo history and one or more carets; every command acts on all carets and a text change is one undoable step. Typing (merging into one undo step), paste (line endings converted; one line per caret when the counts match), Enter with indentation, Backspace/Delete by character cluster (emoji, combining marks and CRLF count as one), word and line deletions (overlapping ones join), Tab/Shift-Tab, cut/copy (whole lines with no selection), movement by cluster, word, line, page and document with a goal column, mouse-gesture selections (click, add, drag, word, line), outside edits (formatter, quick fixes) carried through the carets, and undo/redo restoring selections. Verified against a hand-rebuilt string and for valid carets plus undo/redo consistency under random command sequences.
- 2026-10-27: M1.5 `cargo xtask conformance xmlconf`: fetches the W3C suite (pinned by URL and SHA-256), runs every applicable test through the editor's own path (encoding detection, decoding, parser), and keeps `xtask/baselines/xmlconf.txt` as a ratchet (a new failure fails, and so does a fixed test still listed). First run found 589 of 1017 not-well-formed documents rejected; fixing missing whitespace between attributes, pseudo-attributes and after a PI target, public identifier characters, colons in PI targets, unknown declarations, entity-value references and parameter-entity references inside declarations brought it to 658, with valid and invalid still at 100%. Also: a plain `encoding="UTF-16"` now matches either byte order. A weekly `conformance.yml` runs it, and `cargo xtask ci` runs it when the suite is present.
- 2026-10-27: M1.4 `xmlcraft-syntax` parser: a lossless, error-tolerant `rowan` tree (its text is the input, byte for byte) and 55 diagnostic codes with stable keys, severities, English templates and byte spans: mismatched, unclosed and stray tags, attribute problems, references and characters XML forbids, comments, CDATA, processing instructions, the XML declaration, DOCTYPE structure, and Namespaces in XML 1.0 (unbound or reserved prefixes, empty bindings, duplicate expanded names). No recursion (an explicit stack; past 1024 levels elements stop nesting in the tree but are still matched) and capped diagnostics. Verified against `xmllint` as a black box: 46 known documents and 300 random markup strings agree on well-formedness; namespace-constraint violations are reported as errors here and as non-fatal there, by design.
- 2026-10-27: M1.3 `xmlcraft-syntax` lexer (L1): total, lossless and restartable. Its whole state is a `Mode`; no token spans a line break, so every line start is a checkpoint. Covers tags, attribute values, references, comments, CDATA, processing instructions, the XML declaration, and DOCTYPE with its internal subset. A tag, an attribute value, the XML declaration, the DOCTYPE and a subset declaration that are left open end at the next `<`; an open comment, CDATA section or processing instruction runs to its terminator or the end of the text. Properties: tokens tile any text exactly, lexing restarts at every token boundary, and it always finishes. The M0.11 release dry run built all six targets after the Windows MSI fix (#4, merged).
- 2026-10-27: M1.1 + M1.2 `xmlcraft-text` (L0): rope buffer with checked byte offsets and edits that return their inverse, undo history that merges typing and trims its oldest steps against a memory budget (the newest step is always kept), and that refuses to undo onto text that changed behind its back, line-ending counts and conversion, and encodings (byte-order mark, then XML declaration, then UTF-8; UTF-16; legacy encodings; unmappable characters are reported, never replaced). Property tests: buffer against a `String`, undo/redo through every text, and "any bytes are either flagged lossy or written back identically". M0.11 dry run: macOS and Linux built; Windows failed on a WiX component rule, fixed in PR #4.
- 2026-10-27: M0.9 automation, CLI and control channel: `xmlcraft-automation` (JSON-Schema checked tool table, `--root` confinement that follows symbolic links, scripts, an opt-in MCP server, the control channel transport with token, deadline and connection limits), `xmlcraft-cli` (`tools`, `run`, `mcp`, `ui`), the egui control plugin (`xmlcraft --control FILE`; state, inspect, click, type, key, command, screenshot, quit), accessibility-tree text snapshots. Driven against the real window end to end.
- 2026-10-27: M0.10 CI: `ci.yml` on Linux, Windows and macOS (first run found a lint only the newer CI compiler reports; fixed). Repo `thorstenhirsch/xmlcraft` created by the owner; history rebased onto its initial commit.
