# xmlcraft-xsd

XML Schema 1.0 (layer L3, no UI, no I/O, compiles for the web).

**The reader (M3.3):** `read(text, location)` reads one schema document into the model of `xmlcraft_xsd::model` — the `xs:schema` element with its `targetNamespace`, form and derivation defaults; the includes, imports and redefinitions; and the declarations and definitions: simple types (restriction with facets, list, union), complex types (simple content, complex content, direct content, extension and restriction), model groups (`sequence`, `choice`, `all`, group references, wildcards), elements and attributes (global and local, references), attribute groups, identity constraints (`unique`, `key`, `keyref` with selector and fields), notations, and annotations (the documentation text, with language and source). Every part has the byte range where it was written, and a name's range separately, for diagnostics and go-to-definition.

- **Representation constraints** are checked while reading: which elements may be where and in what order (a child that belongs to a later part is taken there instead of being dropped), the attributes each element may have (and that `id`s are NCNames and unique), the values of the attributes (`minOccurs`/`maxOccurs`, booleans, `form`, `use`, `processContents`, the `block` and `final` sets, `namespace` lists, URI references, qualified names with their prefixes resolved where they are written), and the attributes that may not be given together (`ref` with `type`, `default` with `fixed`, `type` with an inline type, `default` with a `use` other than optional, …). The diagnostics have codes `xsd.*` (see `xmlcraft_syntax::Code`) and the byte span of the element, attribute or value.
- **Total:** whatever the text, the reader returns diagnostics and what it could read; a document that is not well-formed is read as far as the parser got, with the parser's diagnostics first. Nesting is limited to 256 levels and the document to 2 million elements (`xsd.limit`).
- **Qualified names** in attribute values (`type`, `ref`, `base`, `itemType`, `memberTypes`, `substitutionGroup`, `refer`) are resolved to expanded names as the namespace declarations in scope at the element say; an unprefixed name is in the default namespace, if there is one. The declarations in scope are kept where a value holds a name that is read later (a facet's value, a default, the XPath of an identity constraint).

**The documents of a schema (M3.4):** `load(text, location, &mut loader)` reads a schema document and follows its `xs:include`, `xs:import` and `xs:redefine` through a `SchemaLoader` (the caller's way to get a document: the resolver, a file, a test's map). It returns `Documents`: every document once, with the namespace its components are in, the imports it made and the documents that include it. A document without a target namespace that is included into one with a namespace is a *chameleon*: it is kept once per namespace it was included into, and its unqualified references take that namespace. Mistakes (a document that cannot be loaded, an include in another namespace, an import of the schema's own namespace, a document that is not a schema) are reported with the document they were found in. The number of documents (256) and their total size (64 MiB) are limited (`xsd.too-many-documents`).

**The components (M3.5):** `assemble(&documents)` puts the documents together into a `schema::Schema` and reports what is wrong with the components (`Assembly { schema, diagnostics }`). Components refer to each other by number (`TypeId`, `ElementId`, `AttributeId`, `ConstraintId`) into the tables of the schema; everything keeps where it was written (`Origin`).

- **Types:** the 45 built-in types come first (`xs:anyType` is number 0). A type is built when something first needs it complete, so definitions can come in any order; a definition that derives from itself is reported once (`xsd.circular-definition`), and one that depends on a chain of more than 400 others is refused (`xsd.too-deep`). Simple types are restrictions (facets as `xmlcraft-datatypes` defines them), lists and unions; a restriction whose facets do not fit its base is reported and stands for its base, so what uses it is not reported as well. `final` and `finalDefault` stop derivations. Complex types have a *content type* (empty, simple, element-only, mixed) with the content model as a tree of particles (group references expanded, at most 500,000 particles in all), and the attribute uses and the attribute wildcard. Derivation by extension adds the particle of the extension after the base's (and the attributes after the base's, the wildcards joined by union); by restriction the type has the particle and the wildcard it writes and the attributes of the base it does not redeclare or prohibit. Simple content extends or restricts a type with simple content (or a simple type), and may turn the text of a mixed type that can be empty into a simple type.
- **Names** are looked up in the namespace of the document, the language's and the imported ones; a name from another namespace the document does not import is reported (`xsd.namespace-not-imported`), as are unknown names and a type of the wrong kind.
- **Wildcards** (`##any`, `##other`, lists with `##local` and `##targetNamespace`) are sets of namespaces; the intersection (attribute groups, a type's own `anyAttribute`) and the union (extensions) are exact over the namespaces, and one that cannot be written as a wildcard is reported.
- **Elements:** global elements are numbered first, so elements can refer to each other and to types that contain them; a local element in an anonymous type is built after the type that holds it, so a model group whose element's type uses the group is not a cycle. Substitution groups give an untyped member the type of its head, and a member's type must be derived from the head's. `form`, `elementFormDefault`, `block`, `final` and their defaults, `nillable` and `abstract` are kept.
- **Values:** the default or fixed value of an element or attribute is checked against its type once the type is complete (an element whose type has only elements, or an `ID`, cannot have one).
- **Identity constraints** (`unique`, `key`, `keyref`) are kept with their selector, fields and namespace declarations; a keyref's `refer` is resolved to a key or unique constraint with the same number of fields. Notations are declared.

**Not yet:** `xs:redefine` is read and loaded but the redefining definitions are not applied (a warning, `xsd.unsupported`); a restriction is not checked against its base's content model (particle restriction, "Derivation Valid (Restriction)"), nor is the `final` of a substitution group's head applied to the derivation of its members' types; the unique-particle-attribution and element-declarations-consistent checks come with the compilation to content-model automata (M3.7); the XPath of identity constraints is not parsed yet (M3.8); validation of documents (M3.9).

Tests: `tests/components.rs` and `tests/types.rs` (the assembled schema and each mistake), `tests/loader.rs` (includes, imports, chameleons, limits), `tests/reader.rs` (the model and each mistake), `tests/bundled.rs` (the schemas that ship with the app read without a diagnostic), `tests/properties.rs` (damaged schemas, markup soup, deep and wide documents never panic).
