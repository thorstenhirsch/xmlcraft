# xmlcraft-xsd

XML Schema 1.0 (layer L3, no UI, no I/O, compiles for the web).

**What is here (M3.3):** `read(text, location)` reads one schema document into the model of `xmlcraft_xsd::model` — the `xs:schema` element with its `targetNamespace`, form and derivation defaults; the includes, imports and redefinitions; and the declarations and definitions: simple types (restriction with facets, list, union), complex types (simple content, complex content, direct content, extension and restriction), model groups (`sequence`, `choice`, `all`, group references, wildcards), elements and attributes (global and local, references), attribute groups, identity constraints (`unique`, `key`, `keyref` with selector and fields), notations, and annotations (the documentation text, with language and source). Every part has the byte range where it was written, and a name's range separately, for diagnostics and go-to-definition.

- **Representation constraints** are checked while reading: which elements may be where and in what order (a child that belongs to a later part is taken there instead of being dropped), the attributes each element may have (and that `id`s are NCNames and unique), the values of the attributes (`minOccurs`/`maxOccurs`, booleans, `form`, `use`, `processContents`, the `block` and `final` sets, `namespace` lists, URI references, qualified names with their prefixes resolved where they are written), and the attributes that may not be given together (`ref` with `type`, `default` with `fixed`, `type` with an inline type, `default` with a `use` other than optional, …). The diagnostics have codes `xsd.*` (see `xmlcraft_syntax::Code`) and the byte span of the element, attribute or value.
- **Total:** whatever the text, the reader returns diagnostics and what it could read; a document that is not well-formed is read as far as the parser got, with the parser's diagnostics first. Nesting is limited to 256 levels and the document to 2 million elements (`xsd.limit`).
- **Qualified names** in attribute values (`type`, `ref`, `base`, `itemType`, `memberTypes`, `substitutionGroup`, `refer`) are resolved to expanded names as the namespace declarations in scope at the element say; an unprefixed name is in the default namespace, if there is one. The declarations in scope are kept where a value holds a name that is read later (a facet's value, a default, the XPath of an identity constraint).

**Not yet** (the next steps of M3): following includes, imports and redefinitions and putting the documents together (M3.4); resolving names, deriving types, checking the schema component constraints (M3.5, M3.6); compiling to the grammar with the content-model automata and the unique-particle-attribution check (M3.7); identity constraints (M3.8); validation (M3.9).

Tests: `tests/reader.rs` (the model and each mistake), `tests/bundled.rs` (the schemas that ship with the app read without a diagnostic), `tests/properties.rs` (damaged schemas, markup soup, deep and wide documents never panic).
