# xmlcraft-query

XPath 3.1 evaluation for XmlCraft on the `xee` engine (layer L4, no UI, no I/O, compiles for the web).

- `evaluate(xml, expression, &Options)` runs an expression with the document as the context item and returns the items of the result (`ResultItem`): a node has its `kind`, `name` (`Q{uri}local` when it has a namespace), its path as `fn:path` writes it (`/r[1]/i[2]/@n`), its place in the text (`SourceMap`, from the syntax tree of the text; text, references and CDATA are one text node as in the data model; namespace declarations are not attributes; nodes nested deeper than 256 elements have no place and are marked `unmapped`) and, for an element, attribute, comment or processing instruction, its text as written (a text node gives its characters, references resolved); a value has its type (`xs:integer`, …, `map`, `array`, `function`) and its XPath representation. Results are cut at `Options::max_items` (the rest are counted), each text at `max_text` characters, and once `max_total_text` characters are listed no more items are.
- Errors (`QueryError`) have the phase (`Document`, `Compile`, `Run`), the engine's message, and — except a document that cannot be read — the W3C code (`XPST0003`, `FOAR0001`, …) and, when the engine says, the byte range in the expression. Maps, arrays and functions are written by the engine's own writer. The engine has no namespace axis (`XPST0010`).
- `profile(xml, expression, &Options, &Limits)` (and `Prepared::profile`) runs an expression once with the vendored engine's hook (`vendor/README.md`, patch 3) and returns a `Profile`: the result, and for each node of the expression (`probe.rs`: the distinct source spans the compiler gave the instructions, nested by the text) its `hits` (for a node that loops — an axis step for each context item, a predicate for each item it tests, a `for`/`some`/`every` — the items it was evaluated for; else the times the run went into it), the items it produced, the nodes an axis step selected before its predicates, and its self and total cost in engine instructions and (natively) nanoseconds. `nodes` is the tree (text order, each after its parent), `hot` the costliest first. A run over `Limits::max_instructions` (default 50 million) is stopped and says so. A built-in function's own work is the cost of its call; a profiled run is slower than a normal one, which checks one `Option` per instruction.
- `debug::Debugger::start(xml, expression, &Options, Settings)` runs an expression on a worker thread with the same hook and returns a `debug::Session`: it stops when the run goes into a node of the expression or a step, predicate or `for` takes its next item; `step(Action::Into | Over | Out | Continue)`, `pause`, `stop` and `set_breakpoints` (byte offsets: the innermost node there) steer it, and `state()` copies what it shows (the event stopped at, the context item with `position()`/`last()`, the variables read so far that are still alive, the call stack of inline functions, the items the innermost sequence being built has, the last 200 events, the result once it ended). Every wait has a timeout; a paused session ends after an hour, and stopping or dropping one ends its worker (a built-in function that is running finishes first). On the web `start` says it needs a thread.
- XPath 1.0, 2.0 and 3.0 are subsets of the engine's 3.1 and run under its rules (no 1.0 compatibility mode). XQuery is in `xmlcraft-xquery`, which compiles to the same engine and describes its results with `describe_items` (nodes the query built have no path or place and are shown serialized).
- The engine does not read a DOCTYPE: it is blanked (byte for byte) before the document is read, so internal entities are not expanded.
- On wasm the engine's hash maps get their seeds from the browser (`.cargo/config.toml` selects getrandom's `wasm_js` backend).

Tests: `tests/debug.rs` (stepping into visits the nodes in order and each loop once per item, a breakpoint on a predicate stops once per item with what was kept so far, over to the next sibling and out to the parent, a function call's frame and variables, a runaway run paused and stopped with its worker ended, a dropped session, errors and the limit). `tests/profile.rs` (hit counts of a predicate and of steps over a generated shop, the tree and its totals, hot spots and counts that are the same every run, `for` and function bodies, the instruction limit, errors, the same result as an evaluation, a normal evaluation faster than a profiled one; properties: any expression profiled without a panic). `tests/xpath.rs` (nodes with kinds, paths and places for elements, attributes, text with CDATA, comments, processing instructions, namespaced names, the document; values and their types; errors with phases and places; limits; a document with a DOCTYPE; properties: any expression on any text answers or errors without a panic, every node of a generated document is at the place its text says). The tool is tested in `crates/automation/tests/xpath.rs`.
