# xmlcraft-diff

Comparison and merging for XML, JSON and YAML (layer L4, no UI, no I/O, compiles for the web).

- **Lines** (`diff_lines`, `LineOptions`): the longest common subsequence of the lines (Myers' middle snake in linear space, with a budget so that no input takes unbounded time; past the budget the rest is reported as different), the `Hunk`s between the equal lines with the byte range of each in both texts, a unified diff (`LineDiff::unified`), and the words that differ in a changed line (`diff_words`). Options: white space (exact, ends, collapsed, none), case, blank lines. Line endings are never a difference.
- **Trees** (`Node`, `compare_trees`, `compare_documents`, `compare_mixed`): XML as document/element/attribute/text/comment/processing-instruction nodes, JSON and YAML as object/array/scalar nodes, each with its place in the text. Attributes and object members are found by name, children in order (equal ones kept by the longest common subsequence, between them those of the same sort stand for each other), or in any order (`ignore_child_order`). A `Change` is added, removed or changed, with the path (XPath-like for XML, JSON Pointer for data), the places in both texts and the places of the parents. JSON and YAML read into the same trees, so a JSON file can be compared with a YAML file. `TreeOptions`: white space and case of text, comments, processing instructions, child order, numbers by value (`1` = `1.0`), namespace prefixes (the namespaces still compare). Nodes with equal 64-bit hashes (SipHash over kind, name, text and children) are the same.
- **Three-way merge** (`merge3`, `Merge3`, `Region`, `Choice`): base, ours and theirs line by line; a change of one side is taken, the same change of both once, different changes to the same lines are conflicts, written as markers or settled (all alike, or each by its number).
- Never panics, bounded: nesting of elements (256) and the budget of the search.

Tests: `src/seq.rs` (the subsequence against the table method, with a property test and an exhausted budget), `tests/diff.rs` (lines, options, spans, unified output, words, XML and data trees with their places, options, merges; properties: hunks and equal lines cover both texts, a merge with an unchanged side is the other side, the same change on both sides is no conflict, no text panics a comparison). The tools are tested in `crates/automation/tests/diff.rs`.
