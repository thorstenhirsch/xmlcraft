# xmlcraft-diff

Comparison and merging for XML, JSON and YAML (layer L4, no UI, no I/O, compiles for the web).

- **Lines** (`diff_lines`, `LineOptions`): the longest common subsequence of the lines (Myers' middle snake in linear space, with a budget so that no input takes unbounded time; past the budget the rest is reported as different), the `Hunk`s between the equal lines with the byte range of each in both texts, a unified diff (`LineDiff::unified`), and the words that differ in a changed line (`diff_words`). Options: white space (exact, ends, collapsed, none), case, blank lines (they are no difference, and a unified diff shows them where they stand so its counts are right). Line endings are never a difference.
- **Trees** (`Node`, `compare_trees`, `compare_documents`, `compare_mixed`): XML as document/element/attribute/text/comment/processing-instruction nodes, JSON and YAML as object/array/scalar nodes, each with its place in the text. Attributes and object members are found by name, children in order (equal ones kept by the longest common subsequence, between them those of the same sort stand for each other), or in any order (`ignore_child_order`). A `Change` is added, removed or changed, with the path (XPath-like for XML, JSON Pointer for data), the places in both texts and the places of the parents. JSON and YAML read into the same trees, so a JSON file can be compared with a YAML file. `TreeOptions`: white space and case of text and strings, comments, processing instructions, the order of children and array items, numbers by value (`1` = `1.0` = `0x1`), namespace prefixes (the namespaces still compare, `xml:` is its own, declarations are left out). Nodes with equal 128-bit hashes (two SipHash runs over kind, name, text and children) are taken to be the same; a collision (2^-128) is the only way that goes wrong. Moves are shown as a removal and an addition.
- **Three-way merge** (`merge3`, `Merge3`, `Region`, `Choice`): base, ours and theirs line by line; a change of one side is taken, the same change of both once, different changes to the same lines are conflicts, written as markers or settled (all alike, or each by its number). The options of the lines apply (case, white space and blank lines that are ignored are not changes; where only one side differs from the base in a way that is ignored, that side's text stays).
- Bounded and total: nesting of elements (256) and of data (512) is refused beyond that with the place, the search has a work budget, the comparison of children is linear in their number, and no input reaches an index or a slice without a check.

Tests: `src/seq.rs` (the subsequence against the table method, with a property test and an exhausted budget), `tests/diff.rs` (lines, options, spans, unified output, words, XML and data trees with their places, options, merges; properties: hunks and equal lines cover both texts, a merge with an unchanged side is the other side, the same change on both sides is no conflict, no text panics a comparison). The tools are tested in `crates/automation/tests/diff.rs`.
