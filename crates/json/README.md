# xmlcraft-json

JSON Schema for XmlCraft (layer L3, no UI and no I/O, compiles for the web): drafts 04, 06, 07, 2019-09 and 2020-12.

- **A schema set** (`SchemaSet::new(root, base, default_draft, &loader)`): the schema to validate with and the documents it refers to, indexed by `$id` (`id` in draft 4), `$anchor` and `$dynamicAnchor`, and the plain-name `$id` of drafts up to 7. The draft is that of `$schema`, else the default. Referred documents come through a `Loader` (a URI in, text out): what to do for a URI is the caller's, nothing is fetched here.
- **Validating** (`set.validate(&instance)`): the instance is a `xmlcraft_json_syntax::Value`, so every `Violation` has the JSON Pointer of the place in the instance (turn it into a place in the text with `Value::span_of_pointer`), the pointer of the keyword in the schema (for a `false` schema, which has no keyword, the pointer of the schema itself and the keyword `false`), the keyword and a message.
- **Keywords:** `type`, `enum`, `const`, `multipleOf`, `minimum`/`maximum`, `exclusiveMinimum`/`exclusiveMaximum` (a flag in draft 4), `minLength`/`maxLength`, `pattern`, `items` (list and schema form), `prefixItems`, `additionalItems`, `contains` with `minContains` and `maxContains`, `minItems`/`maxItems`, `uniqueItems`, `properties`, `patternProperties`, `additionalProperties`, `required`, `minProperties`/`maxProperties`, `propertyNames`, `dependencies`, `dependentRequired`, `dependentSchemas`, `allOf`, `anyOf`, `oneOf`, `not`, `if`/`then`/`else`, `$ref` (also `$recursiveRef` and `$dynamicRef`, with their scopes), `unevaluatedProperties` and `unevaluatedItems` (with the annotations of the keywords that evaluate places, also through `$ref`, `allOf`, `anyOf`, `oneOf` and `if`).
- **Differences between drafts are kept:** a `$ref` hides its siblings (and an `$id` beside it) up to draft 7; `1.0` is an integer since draft 6; a boolean schema is evaluated in every draft (before draft 6 only `additionalProperties` and `additionalItems` may have one).
- **Numbers** are compared exactly (`0.0075` is a multiple of `0.0001`, `1.0` equals `1`, numbers beyond 64 bits are compared as written) and as `f64` only when they have more than 36 digits.
- **Limits:** nesting (200), evaluations (5 million), the size of a pattern (1 MiB compiled), the number of documents (64) and of violations (1000) are capped, and a result that was cut off says so (`Outcome::truncated`). A schema that refers to itself without progress ends the same way.
- **Not here:** `format` is an annotation only (no assertions yet), `contentEncoding`/`contentMediaType`/`contentSchema` are annotations, patterns are those of Rust's `regex` crate (no look-around or back-references; a pattern that does not compile is ignored), vocabularies (`$vocabulary`, custom meta-schemas) are not honoured, and the meta-schemas are bundled by `xmlcraft-schemas` (the caller's `Loader` hands them out), not by this crate.

Measured by `cargo xtask conformance jsonschema` (the JSON Schema Test Suite, fetched, never committed; the required tests of drafts 4 to 2020-12): 99.96% (4948 of 4950, with the bundled meta-schemas given to the loader); the 2 known failures (`xtask/baselines/jsonschema.txt`) are the tests that need custom vocabularies. Unit and property tests: `tests/validate.rs` (each keyword, the places of violations, references, unevaluated places, the caps, and random schemas against random instances that never panic and always point at places that exist).
